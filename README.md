## 3. Анализ HTTP-ответов

После выполнения запроса сервер возвращает HTTP-ответ, в котором содержатся статус-код, заголовки и тело ответа. Для
анализа были выбраны два запроса: один нв поиска курса в каталоге и один на запись на выбранный курса.

### 3.1. Пример анализа ответа на запрос страницы

Для запроса поиска был получен ответ со статусом 200 OK. Это указывает на успешную загрузку
страницы, после чего браузер начал рендерить интерфейс.

Основные наблюдаемые заголовки:

- Content-Type: application/json;
- Cache-Control: политика кэширования содержимого;
- Expires: политика кэширования содержимого;
- Date: дата и время ответа;
- Server: название серверного программного обеспечения;

Тело ответа представляло JSON-объект, содержащиий все курсы найденные в раммках фильтра.

### 3.2. Пример анализа ответа на запрос записи на курс.

Для API-запроса, связанного с записью на курс, был получен ответ со статусом 201 Created, что соответствует успешной операции.
Это означает, что сервер подтвердил выполнение действия и передал результат в формате JSON.

```json
{
  "id": 4852,
  "course": 4852
  "progress": "78-4852",
  "price": null,
}
```

### 3.3. Наблюдаемые факты и предположения

Наблюдаемый факт: сервер возвращает JSON-ответ на запись на курс.

Предположение: backend выполняет проверку авторизорован ли пользователь, не записан ли он уже на этот курс, сохраняет новое состаяние и возвращает данные пользователю о зачислении.

## 4. Анализ параметров и передаваемых данных

При выполнении пользовательского сценария браузер передавал серверу информацию, которая позволяла понять, какой объект
ищется и какое действие нужно выполнить.

### 4.1. Параметры запроса

В запросах, связанных с записью на курса, можно выделить следующие типы параметров:

В теле запроса:

- индефикатор курса;
- идентификатор страницы;

В заголовках:

- время операции;
- версия браузера;
- поддерживаемые кодировки;
- Content-type (тип передаваемых данных);
- идентификатор сессии (внутри cookie).

### 4.2. Где находятся данные

Параметры были расположены следующим образом:

- часть данных — в URL-параметрах query string;
- основная часть данных — в теле HTTP-запроса (payload) в формате JSON;
- служебные данные — в cookie и заголовках запроса.

Пример структуры данных в body запроса:

```
{
  "course": 4852
}
```

### 4.3. Какие данные передаются при записи на курс

- индефикатор курса, на который записывается пользователь;
- индефикатор пользователя
- стоимость курса;
- информация об оплате;

## 5. Анализ cookies

Cookies используются в веб-приложениях для хранения небольших данных, которые браузер должен отправлять серверу при
последующих запросах. В Stepik это может использоваться для идентификации сессии, аналитики и хранения
пользовательских настроек.
